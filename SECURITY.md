# Security

## Reporting a vulnerability

Please do **not** open a public issue. Report it privately with GitHub's
"Report a vulnerability" button on this repository, or by email to the
maintainer listed in `package.json`. Include a description, the affected
versions and, if you can, a proof of concept. You'll get an answer within a
week. Fixes ship as patch releases of both the npm package and the crate.

## What this plugin protects

The asset is the **app session token**: a Better Auth session usable as
`Authorization: Bearer`. The goals:

1. Only the app instance that started a sign-in can finish it.
2. The token never reaches the webview, logs, events or disk outside the
   secret store.
3. Nothing outside the app's own configuration can change where the app sends
   credentials.

## Threat model

| Threat                                                                              | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Another local app registers the same URL scheme and intercepts the deep link        | The code is useless without the PKCE verifier, which never leaves the app process (RFC 8252 §8.1). Codes are single-use and expire in 5 minutes.                                                                                                                                                                                                                                                                      |
| A local app starts its own sign-in, hoping the user approves it                     | The hand-off page requires an explicit "Continue as <email>" click after every login. The page tells users to continue only if they just clicked "Sign in" in the app.                                                                                                                                                                                                                                                |
| A crafted sign-in link with a remote `redirect_uri` sends the code to an attacker   | The page only follows `http://127.0.0.1:<port>/…` or `http://[::1]:<port>/…` in their literal form; anything else fails. The custom scheme comes from the page's own configuration, never from the URL.                                                                                                                                                                                                               |
| Phishing for the copy-paste code                                                    | The page shows the code only on request, with a "never share this code" warning. The code is single-use and expires in 5 minutes, and it is bound to a verifier the attacker doesn't have.                                                                                                                                                                                                                            |
| Script on another trusted subdomain (docs, blog) mints codes with the user's cookie | `authorizeOrigins` limits `/tauri/authorize` to the hand-off page origin.                                                                                                                                                                                                                                                                                                                                             |
| A revoked browser session still authorizes because of the cookie cache              | `/tauri/authorize` checks the session against the database (`sensitiveSessionMiddleware`).                                                                                                                                                                                                                                                                                                                            |
| Login CSRF: swapping a victim's app session for the attacker's account              | The callback `state` must match the app's pending state (constant-time). The app shows the signed-in account.                                                                                                                                                                                                                                                                                                         |
| Replay or races on a code                                                           | The code is consumed atomically (database transaction, or atomic `getAndDelete` in secondary storage) before any check. Concurrent exchanges cannot both win.                                                                                                                                                                                                                                                         |
| Brute-forcing codes                                                                 | 32 characters of `[A-Za-z0-9]` (~190 bits), a 5-minute lifetime, the code burned on the first attempt, and per-IP rate limits.                                                                                                                                                                                                                                                                                        |
| Fake deep links (denial of service, spam)                                           | A link that doesn't match the pending state is ignored without events, focus changes or clearing the pending sign-in.                                                                                                                                                                                                                                                                                                 |
| Redirects forwarding the verifier or token                                          | No HTTP client in the plugin follows redirects. Better Auth's client-side redirect plugin is disabled in the webview.                                                                                                                                                                                                                                                                                                 |
| Plain-text transport                                                                | https is required everywhere except loopback hosts. TLS uses rustls with the OS certificate verifier.                                                                                                                                                                                                                                                                                                                 |
| Cross-site scripting in the webview steals the token                                | There is no command that returns the token. The bridge strips `set-auth-token` and `set-cookie`, rebuilds auth responses from known fields, scrubs credential-shaped keys, and refuses every auth route outside its allowlist, including `/tauri/*`, one-time tokens, session lists and OAuth token endpoints. Injected script can make bridged calls while it runs, but it cannot take a long-lived credential away. |
| Injected script redirects the exchange to its own server                            | URLs, scheme and client id are set in Rust only. Commands never accept them.                                                                                                                                                                                                                                                                                                                                          |
| Token in logs or crash dumps                                                        | `Debug` implementations redact secrets. Log lines never include tokens, codes, states, verifiers or device ids. Bearer header values are marked sensitive.                                                                                                                                                                                                                                                            |
| Stale credentials after a failed sign-out                                           | The server session is revoked, the secret deleted, and a revision tombstone written. If deletion fails, the tombstone prevents rehydration.                                                                                                                                                                                                                                                                           |
| An old session revoked before its replacement is safely stored                      | The order is store new, then revoke old. If storing fails, the _new_ session is revoked and the old one kept.                                                                                                                                                                                                                                                                                                         |
| A cancelled or outdated sign-in completes later                                     | A generation counter plus one commit lock: cancel, sign-out and every commit are serialized. An outdated result is discarded and its session revoked.                                                                                                                                                                                                                                                                 |

## Things this plugin cannot do

- **A compromised machine** (malware running as the user) can read the
  keychain, the webview and process memory. No desktop auth scheme defends
  against that.
- **Your own API** must not return credentials. The bridge forwards app API
  responses unchanged, apart from header stripping.
- **Server-side policy** (device limits, plan checks) belongs in your
  `databaseHooks.session.create.before`. The plugin runs it in the exchange
  request, so a rejection happens before any credential exists.
